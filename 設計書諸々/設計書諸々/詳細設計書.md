# 詳細設計書

## メソッド命名規則

### Controllerメソッド命名規則
```
{HTTPメソッド}{機能名}
```
- 例: `createRecord`, `getAllRecords`, `getRecordsByMonth`, `updateRecord`, `deleteRecord`

### Serviceメソッド命名規則
```
{機能名}{対象}
```
- 例: `createRecord`, `getAllRecords`, `getRecordsByMonth`, `updateById`, `deleteRecord`

### Repositoryメソッド命名規則
```
{操作}{対象}
```
- 例: `insert`, `findAll`, `findByMonth`, `updateById`, `deleteById`

## 実装済みメソッド一覧

### Controller (MoneyRecordController)

| メソッド名 | HTTPメソッド | エンドポイント | 役割 | 引数 | 戻り値 |
|-----------|--------------|---------------|------|------|--------|
| `createRecord` | POST | `/api/money-records` | 家計簿記録を登録 | `@Valid @RequestBody MoneyRecordCreateRequest` | `void` |
| `getAllRecords` | GET | `/api/money-records` | 全ての家計簿記録を取得 | なし | `List<MoneyRecordResponse>` |
| `getRecordsByMonth` | GET | `/api/money-records/month/{year}/{month}` | 指定した月の家計簿記録を取得 | `@PathVariable int year, int month` | `List<MoneyRecordResponse>` |
| `getRecordsByDay` | GET | `/api/money-records/day/{date}` | 指定した日付の家計簿記録を取得 | `@PathVariable LocalDate date` | `List<MoneyRecordResponse>` |
| `deleteRecord` | DELETE | `/api/money-records/{id}` | 指定したIDの家計簿記録を削除 | `@PathVariable Long id` | `void` |
| `updateRecord` | PUT | `/api/money-records/{id}` | 指定したIDの家計簿記録を更新 | `@PathVariable Long id, @Valid @RequestBody MoneyRecordUpdateRequest` | `void` |

## テストで使用する主なライブラリ・メソッド

### JUnit 5
- `@Test` - テストメソッドを示すアノテーション
- `assertEquals(expected, actual)` - 値が等しいことを検証

### Mockito
- `@Mock` - モックオブジェクトを作成
- `@InjectMocks` - モックを注入する対象
- `@MockBean` - Springコンテキスト用のモック
- `when(mock.method()).thenReturn(value)` - モックの戻り値を設定
- `doNothing().when(mock).method()` - voidメソッドのモック設定
- `verify(mock).method()` - メソッドが呼ばれたことを検証
- `verify(mock, times(n)).method()` - メソッドがn回呼ばれたことを検証
- `any(Class)` - 任意の引数をマッチ

### Spring Boot Test
- `@WebMvcTest(Controller.class)` - Controllerレイヤーのテスト
- `@ExtendWith(MockitoExtension.class)` - Mockito拡張機能を有効化

### MockMvc
- `mockMvc.perform(request)` - リクエストを実行
- `get(url)` - GETリクエストビルダー
- `post(url)` - POSTリクエストビルダー
- `put(url)` - PUTリクエストビルダー
- `delete(url)` - DELETEリクエストビルダー
- `.contentType(MediaType.APPLICATION_JSON)` - Content-Typeヘッダー設定
- `.content(jsonString)` - リクエストボディ設定
- `.andExpect(status().isOk())` - ステータスコード200を検証
- `.andExpect(status().isBadRequest())` - ステータスコード400を検証
- `.andExpect(jsonPath("$.field").value(value))` - JSONレスポンスを検証

### ObjectMapper
- `objectMapper.writeValueAsString(object)` - JavaオブジェクトをJSON文字列に変換

## テスト構成のベストプラクティス

### Controllerテスト
1. テストデータの準備
2. Serviceのモック設定（`when()`）
3. HTTPリクエストの実行（`mockMvc.perform()`）
4. レスポンスの検証（`andExpect()`）
5. Serviceメソッド呼び出しの検証（`verify()`）

### Serviceテスト
1. テストデータの準備
2. Repositoryのモック設定（`when()` または `doNothing()`）
3. Serviceメソッドの実行
4. Repositoryメソッド呼び出しの検証（`verify()`）
5. 必要に応じて戻り値の検証（`assertEquals()`）
