# 次のステップ計画（設計書整備 / Phase1完成度UP / UI/UX改善）

設計書の不足・誤りを整理したうえで、月別・日別取得機能をフロントに繋ぎ込み（テスト含む）、最後に最小限UIをモダン化する3段階の計画です。

## 現状サマリ

- **バックエンドAPI（実装済）**: `createRecord` / `getAllRecords` / `getRecordsByMonth` / `getRecordsByDay` / `deleteRecord` / `updateRecord`
- **フロントエンド（実装済）**: 一覧表示+更新+削除（`MoneyRecordList.tsx`）、登録フォーム（`MoneyRecordForm.tsx`）
- **テスト（9件）**: Controller 5件 / Service 4件
- **未対応**: 月別・日別取得はAPIのみ存在しフロント未使用・テストなし。UIは最小限の素のHTML。

## 検出した設計書・コードの不整合（整備対象）

- **テストエンドポイント誤記**: `詳細設計書.md` の「今後追加すべきテスト」で月別が `/api/money-records/month` となっているが、実際は `/month/{year}/{month}`、日別は `/day/{date}`。
- **memoの必須/任意の不一致**: バックエンドDTOは `memo` 任意（`@NotBlank`なし）だが、フロント型 `MoneyRecordResponse/CreateRequest/UpdateRequest` では `memo: string`（必須扱い）。
- **登録後の再描画**: `MoneyRecordForm` が `window.location.reload()` で全リロード。一覧の状態管理と整合していない。
- **設計書の対象範囲**: gitignore対象（`設計書諸々/`）のため、編集時は一時的に `.gitignore` のコメントアウト→編集→戻す既存手順を踏む。

## Git運用

- 各ステップごとに feature ブランチを作成（例: `feature/month-day-fetch`, `feature/ui-improvement`）。
- 実装→テスト→コミット→プッシュ→`develop`マージ→originプッシュ。
- 設計書のみの変更はコミット対象外（gitignore）だが、`進捗.md` 等の運用は既存手順に従う。
